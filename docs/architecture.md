# Architecture & Algorithms

## Architecture Decision Records (ADR)

### 1. Containerization (Docker)
- **Context**: The application depends on system-level libraries (FFmpeg, PortAudio, OpenCV) and hardware access (V4L2, ALSA).
- **Decision**: Use Docker and Docker Compose.
- **Rationale**:
  - **Consistency**: Ensures identical environment across dev (x86) and prod (RPi ARM64).
  - **Isolation**: Prevents dependency conflicts with host system.
  - **Trade-off**: Requires privileged mode/device mapping for hardware access, which can be tricky on some systems.

### 2. Dependency Management (Poetry)
- **Context**: Python dependency management can be fragile with `pip` + `requirements.txt`.
- **Decision**: Use Poetry.
- **Rationale**:
  - **Locking**: `poetry.lock` ensures exact version reproducibility.
  - **DX**: Simplifies virtualenv management and separating dev/prod deps.
  - **Packaging**: Standardized `pyproject.toml` configuration.
  - **Trade-off**: Slightly higher learning curve than vanilla pip.

### 3. Video Streaming (Go2RTC vs Alternatives)
- **Context**: Need generic low-latency streaming to browser and internal consumption for processing.
- **Decision**: Use **Go2RTC**.
- **Rationale**:
  - **WebRTC**: Native low-latency streaming to browsers (<500ms).
  - **Multiplexing**: Can consume one hardware device and restream via RTSP/WebRTC to multiple clients (bbwatch + user).
  - **Simplicity**: Single binary, YAML config, unlike GStreamer pipelines.
  - **Trade-off**: Does not perform transcoding/processing itself; relies on external FFmpeg.
- **Alternatives Considered**:
  - **ROS2**: Too heavy/complex for a simple appliance. Overkill for single-cam setup.
  - **DeepStream**: NVIDIA-specific. We target Raspberry Pi (CPU/Broadcom).
  - **GStreamer**: Powerful but complex pipeline management. Hard to serve WebRTC easily without helper servers (like Janus).
  - **MJPEG**: High bandwidth, no audio support in same stream.

### 4. Configuration (Pydantic)
- **Context**: Application requires strict parameter validation (types, ranges) to avoid runtime hardware errors.
- **Decision**: Use Pydantic.
- **Rationale**:
  - **Validation**: Runtime type checking and range validation (e.g., `history_len >= 1`).
  - **Environment**: Native support for checking/overriding via env vars.
  - **Schema**: Autogenerated schema for potential frontend generation.

## Perception Algorithms

### Libraries
- **OpenCV**: 
  - Used for: Video capture, resizing, frame differencing, overlay drawing.
  - Why: Industry standard, highly optimized C++ backend, Python bindings are efficient wrappers.
  - Alternatives: `PIL` (too slow for video), `scikit-image` (more for offline analysis).
- **SoundDevice / SoundFile**:
  - Used for: Audio capture and WAV writing.
  - Why: `sounddevice` wraps PortAudio cleanly. `soundfile` is robust for wav encoding.
  - Alternatives: `PyAudio` (older, heavier), `wave` (std lib, but manual header management).

### Current Algorithms

#### 1. Audio Event Detection (Cry)
No ML is currently used. We use Digital Signal Processing (DSP).
1.  **Capture**: Sliding window buffer (3s default).
2.  **Filtering**: Bandpass filter (Butterworth) extracting 250Hz - 800Hz (typical fundamental frequency of infant cry).
3.  **Analysis**:
    - **RMS Energy**: Calculate Root Mean Square amplitude of filtered signal.
    - **Threshold**: If RMS > `rms_threshold` (e.g., 0.02).
    - **Duration**: If signal remains above threshold for >30% of window.
4.  **Result**: Boolean trigger.
- **Limitation**: Can trigger on loud adult speech or sirens in same frequency range.

#### 2. Visual Motion Detection
1.  **Preprocessing**: Grayscale conversion + Gaussian Blur (reduce noise).
2.  **Differencing**: `absdiff(current_frame, previous_frame)`.
3.  **Thresholding**: Binary threshold on difference map.
4.  **Morphology**: Dilation to fill gaps in motion blobs.
5.  **metric**: Count changed pixels / total pixels.
- **Limitation**: Sensitive to sudden lighting changes (cloud/sun) or camera auto-exposure adjustments.

### Future Roadmap (Neural Networks)

To reduce false positives, we plan to move to NN-based interference:

1.  **Audio Classification**:
    - **Model**: **YAMNet** (TensorFlow Lite).
    - **Class**: "Baby cry, infant cry".
    - **Why**: Pre-trained on AudioSet, runs efficiently on RPi CPU.

2.  **Person/Pose Detection**:
    - **Model**: **MobileNet SSD** or **YOLOv8-Nano**.
    - **Goal**: Verify if a person is in the crib vs moving curtain/pet.
    - **Why**: Specialized edge-optimized models run near real-time on RPi 4.
